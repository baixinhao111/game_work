> **文档目的**：明确从 0 到 1 实现《周一突围：DDL 战线》手机网页版的研发节奏、各阶段不可妥协的验收标准（Definition of Done）、数值与性能压测方案，以及潜在研发风险的兜底预案。

## 1. 五阶段研发里程碑规划（M0 – M4）

### M0：宏观规划与项目立项基线（当前阶段）
- **核心目标**：完成品类与年轻用户痛点调研、确立完整 GDD 玩法与数值模型、敲定手机端 H5 技术架构。
- **核心交付物**：
  - `README.md` 项目总览
  - `docs/01-market-and-player-research.md`
  - `docs/02-game-design-document.md`
  - `docs/03-technical-architecture.md`

- **验收标准（DoD）**：
  - 文档体系完整覆盖玩法、数值公式、美术色板、模块目录与 TS 接口草案，无待定占位符；经项目发起人审阅确认后冻结 M1 核心边界。

---

### M1：核心可玩垂直切片（Vertical Slice）
- **核心目标**：以极简色块与矢量几何快速跑通**最核心的 30 秒游戏手感**——确保“单指拖拽流畅度、领队零误触选门、射穿红门翻蓝、对象池 60fps”这根主脊梁先立得住。
- **关键工程任务**：
  1. 初始化 `Vite + TypeScript` 工程与 `390×844` 移动端自适应视口（含 `100dvh`、`viewport-fit=cover`、`touch-action: none`）。
  2. 实现 `Loop.ts` 固定步长主循环、`ObjectPool.ts` Swap-Pop 泛型对象池与 `InputManager.ts` 相对位移拖拽。
  3. 落地 `SquadSystem.ts`（费马螺线阵型）与领队单点锚定碰撞 + **同排双门互斥锁**。
  4. 落地基础「订书机速射」、经典蓝门（`+ / ×`）、可射击翻蓝红门（`- / ÷`）与基础炮灰怪「未读 99+」。
- **可量化验收标准（DoD）**：
  - 局域网手机真机打开页面无滚动条、无橡皮筋回弹，单指拖拽延迟感低于 1 帧；
  - 故意压中双门中心线测试 20 次，**0 次出现“同时触发两扇门”或“外围小人刮蹭红门误扣血”**；
  - 红门持续受击数值递增并在 `0` 点翻转为蓝门；
  - 开启 `?debug=1` 查看性能面板，普通战斗下稳定 60fps 且对象池无泄露增长。

---

### M2：Neo-Pop 风格化美学、打击感与“嘴替”注入
- **核心目标**：把“灰盒子原型”彻底变成第一眼就潮酷抓人、音效与吐槽极其上头的独立游戏质感。
- **关键工程任务**：
  1. 落实 **Art Bible** 色板与 `SpriteCache.ts` 离屏预渲染（`2.5–3px` 深墨粗描边、`45°` 硬贴纸投影、斜向透视日程跑道滚动刻度）。
  2. 实现小队超过 `24` 人时的 5 合 1「冰美式突击手」与 10 合 1「机械键盘机甲」视觉代理进化。
  3. 注入全部 **Game Feel** 反馈：受击 `60ms` 白闪、`30–45ms` 关键顿帧、弹簧震屏、暴击放大飘字与 Android 震动反馈。
  4. 构建 `AudioEngine.ts`：实现 Web Audio 同步解锁 + 全套程序化音效（重点调优**射击红门时的五声音阶逐级升调反馈**）。
  5. 接入 `QuipSystem.ts`“嘴替”实时弹幕吐槽横幅与 `4s` 冷却防刷屏控制。
- **可量化验收标准（DoD）**：
  - iOS Safari 与微信内置浏览器真机实测：点击开始按钮后**首次操作 100% 正常出声**，无静音锁死；
  - 画面完全脱离传统买量广告质感，静态截图在手机上具备清晰的视觉分层（0.5 秒内能分清增益门、减益门与敌方弹幕）；
  - 击碎红门翻蓝的音阶上升听感清脆连贯、无破音爆音。

---

### M3：完整 5 天主线关卡、肉鸽构筑、养成与战报系统
- **核心目标**：补全全部玩法深度与“局外循环 + 社交传播”闭环，打造可完整游玩数十分钟的成品级内容体量。
- **关键工程任务**：
  1. 完成 **6 大武器原型**（订书机/机械键盘/冰美式/外卖无人机/降噪耳机/AI 浮游炮）与 **8 个轻肉鸽词条**、**5 组化学反应**及亚线性 DPS 合并逻辑。
  2. 完成剩余特殊机关（空投补给桶、赌狗盲盒门 `???`、滑轨移动门、过载风险门、联动跷跷板门、下班充能门）与「准点下班」全屏大招。
  3. 完成 5 种普通/精英怪与 **周一至周五 5 大主题 Boss**，并填充 `day1.ts` ~ `day5.ts` 数据驱动关卡配置。
  4. 上线「周末无尽加班模式」、`SaveManager.ts` `localStorage` 永久存档与 4 项摸鱼天赋升级界面。
  5. 完成 `PosterExporter.ts` 离屏生成 `750×1200`「今日摸鱼战报」海报，支持 `<img>` 长按保存。
- **可量化验收标准（DoD）**：
  - 从周一第 1 关一路打通周五 Boss 并解锁周末无尽模式，全流程无死锁、无未捕获异常；
  - 任意触发至少 3 组「化学反应」均有明显弹幕质变与弹窗提示；
  - 离线刷新页面后咖啡豆数量、天赋等级与解锁关卡完整保留；
  - 局末可正常生成清晰无错位的「今日摸鱼战报」图片，长按可保存至手机相册。

---

### M4：多端真机压测、数值调优与发布就绪
- **核心目标**：通过极限边界压测与多浏览器真机清障，确保上线即稳如磐石。
- **关键工程任务**：
  1. 执行全量边界数值测试与 500 人大军压力测试，调优周一至周五每一关的门槛难度曲线（防止第 3 关突兀卡死或第 5 关数值溢出秒杀 Boss）。
  2. 清理所有内存峰值与潜在渲染卡顿（排查手机端热降频表现）。
  3. 验证微信内置浏览器、iOS Safari、Android Chrome 全兼容性 Checklist。
  4. 生产构建审计：校验 gzip 产物包体积、PWA `manifest` / 图标元信息配置（可选）。
- **可量化验收标准（DoD）**：
  - 生产环境打包 JS + CSS 总体积 **`< 80 KB (gzip)`**；
  - 500 逻辑人数极限叠加 5 个词条满屏扫射 Boss 时，中端手机端帧率保持 **≥ 50 FPS**；
  - M4 全部兼容性测试项通过率 **100%**。

## 2. 测试与数值调优专项方案

### 2.1 移动端真机验证清单
每次重要里程碑交付前，通过 Vite `--host` 开启局域网预览，使用真实手机覆盖以下测试场景：
1. **iPhone（iOS Safari + 微信内置 WKWebView）**：验证静音键开启/关闭状态下的 Web Audio 解锁、底部 Home Indicator 安全区避让、横向剧烈拖拽是否意外触发 Safari 左边缘“返回上一页”手势。
2. **中低端 Android（Chrome + 微信 X5 内核）**：验证 `DPR<=2` 限制下的清晰度与持续游玩 5 分钟后的发热掉帧情况、Vibration API 震感强度是否舒适不扰民。
3. **PC 桌面端（Chrome / Edge）**：验证居中竖屏容器美观度、鼠标拖拽及键盘方向键调试体验。

### 2.2 数值边界与极限场景测试用例
| 测试用例编号 | 极限场景描述 | 期望系统表现（Pass 条件） |
| :---: | :--- | :--- |
| **CASE-01** | **1 人残血保底验证**：仅有 `1` 名小人时撞进 `-20` 或 `÷2` 红门 | 若当前有护盾则消耗 1 层护盾并保底人数不变；若无护盾则扣除至保底阈值规则触发或清晰进入 `DEFEAT`（绝不出现 `NaN`、`0.5` 小数人数或负数小人渲染） |
| **CASE-02** | **500 人极限弹幕压测**：在无尽模式将逻辑人数滚到 `500+` 且持有“冰美式 + 连锁闪电 + 分裂” | 屏幕小队渲染数锁死在 `≤ 45` 个（含机甲合体），子弹合并生效且同屏子弹数 `≤ 180`，对象池零新增堆溢出，帧率稳守 `≥ 50 FPS` |
| **CASE-03** | **双门中缝极速甩手**：在距离门 `20px` 处以最快手速横穿中缝 | 领队单点锚定仅触发一侧门，`pairGroupId` 立即锁定另一侧门，绝不连续弹窗加减两次 |
| **CASE-04** | **红门临界值 0 点翻蓝**：门显示 `-1`，最后一发散弹 5 颗同时命中 | 门准确穿过 `0` 翻转为蓝门 `+N` 并继续吸纳多余 4 颗伤害向上累加，不发生跳过翻蓝或负血锁死 |
| **CASE-05** | **切后台与来电打断**：Boss 战进行到一半切出微信回复消息 30 秒后返回 | 返回后游戏处于优雅的 `PAUSED` 界面，点击“继续摸鱼”后跑道时间轴与 Boss 状态零错位、无瞬间瞬移扣血 |

## 3. 核心风险矩阵与应对预案

| 风险类别 | 具体风险描述 | 发生概率 | 影响程度 | 事前预防与事后兜底方案 |
| :--- | :--- | :---: | :---: | :--- |
| **性能风险** | 高倍人数叠加分裂+连锁闪电时，低端安卓机 Canvas 重绘或 `ctx.shadowBlur` 掉帧严重 | 高 | 严重 | 1. 架构硬禁用实时 `shadowBlur`，改用同心半透明线条伪发光；<br>2. 强制开启 5 合 1 / 10 合 1 代理压缩与子弹合并上限；<br>3. 增加“低功耗模式”开关（自动减少 50% 背景装饰粒子）。 |
| **兼容性风险** | 微信内置浏览器拦截 Web Audio 导致全程无声，或下拉露出网页灰底破坏沉浸感 | 高 | 高 | 1. 音频解锁严格写在“开始游戏”按钮 `touchstart` + `touchend` 同步栈内；<br>2. 在 `document` 级挂载 `touchmove` 拦截与 `100dvh` 变量兜底；<br>3. 内置 `?debug=1` 掌上错误浮窗快速定位。 |
| **触控手感风险** | 在 iPhone 边缘滑动躲避最左侧门时，误触发 iOS Safari“右滑返回上一页”系统手势 | 中 | 高 | 跑道左右有效可移动范围比屏幕物理边缘内缩 `18px` 左右留白，配合相对位移拖拽（灵敏度 `1.25`），玩家手指在屏幕中央区域即可轻松将角色移至跑道极左/极右端，无需贴屏边滑动。 |
| **玩法数值风险** | 周一到周五难度曲线过陡导致玩家第 3 关劝退，或拿了超导组合后无脑站撸秒杀 Boss | 中 | 中 | 1. 将 5 天关卡配置全部抽离为纯 TS/JSON 时间轴，支持 `?level=3` 直跳调试；<br>2. 亚线性 `N^0.75` 公式控制火力上限；<br>3. 为 Boss 设定阶段转场护盾（或清兵机制），防止强力 Build 直接一秒蒸发 Boss 丧失机制交互体验。 |
| **美术辨识度风险** | 波普元素过多导致花哨，关键时刻看不清红门数字或 Boss 预警红圈 | 中 | 高 | 严格执行《Art Bible》色相隔离：跑道固定使用低饱和暗夜蓝灰 `#222536`，只有交互门、弹幕与威胁采用高饱和荧光色，且门面数字采用 `700/900` 粗体字加 `3px` 深墨描边，保证 0.5 秒极速扫视可读性。 |
